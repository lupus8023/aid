# 全系列风格参考

系列项目可保存一张 `styleReference.imageUrl` 和可选文字说明。风格图只提供文化与美术气质、色温色调、光线、镜头成像和材质表现，不承担人物身份或具体场景的定义。角色脸型、发色、种族、服装仍由角色资料与身份图控制；室内、夜景、景别和运镜仍服从剧本。

GPT-image-2 的最终请求将风格图放在内容参考之后，并明确标注该图片编号为 STYLE ONLY。项目选定的输出媒介优先，不能从风格图继承 CG 或插画画法。参考容量预留一个风格位置，不能静默丢掉人物参考。MJ 使用独立 sref。风格随单集生产快照保存，Story 生图、视频提示词以及实际视频提交均继承该标准。

更换或移除风格需要任务先暂停并保存断点。旧视觉素材、付费任务编号和生产快照归档到 visualHistory；已有剧本、声音、历史成片不删除。新视觉任务重新生成，避免同一集混入旧风格。

写实系列使用单张定妆照作为角色卡和后续人物参考，不再额外购买不参与制作的多视图拼版。旧拼版和候选保留，已生成图优先复用。

按用户反馈，主观的“CG感/摄影质感”判断只作为建议：不阻断制作，不触发重生成，质检不可用也不造成付费重试。既有低评分候选、以前发生的重试及供应商失败记录保持完整。若后一次请求失败但之前已有供应商成功返回的候选，则直接复用已有候选，不重新请求，也不将供应商审核拒绝伪装成成功。

旧版曾尝试从 CG 卡提取结构化身份说明再生成；该自动路径已停用，避免在几乎相同的图片上重复花费。已经保存的结构说明和结果仍作为历史保留。供应商暂时失败、轮询中断与持久化故障继续由独立的技术恢复逻辑处理，审核拒绝不能通过自动改写绕过。

## 浏览器断点与付费回执

角色/场景图在提交前将 imageSubmissionKey 保存进项目断点。Companion 对同一编号先创建本地独占回执，再向供应商提交，收到任务编号后先落盘再回复浏览器。重载后的执行器复用回执，不重新购买；同一编号不同内容直接拒绝。磁盘仅保存内容哈希、状态、日期和任务编号，不保存密钥或提示词。

如果供应商自身响应丢失且未取得任务编号，系统保留不确定回执，不能声称生成失败，也不能自动重新计费。它需要供应商提供可核对的任务结果。此边界无法靠盲目重试实现可靠的无人值守。

## 回归验证

`tests/series-style-reference.test.mjs` 检查风格归档、参考图角色、最终 GPT/MJ 参数、生产快照及视频台词/结尾约束。
`tests/series-image-submission.test.mjs` 检查并发请求、跨请求恢复、不确定结果、内容冲突、服务中断和审核拒绝均不会重复购买。
`tests/series-runner.test.mjs` 检查单张写实卡进入制作、提交编号先于付费请求保存、完成后不再重复生成。

实际首集仍需对生成的画面、人物一致性、声音和最终 1 秒无配音做完整验收；通过单元测试不等于成片质量已通过。
