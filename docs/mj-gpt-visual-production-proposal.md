# MJ 审美定稿 + GPT-Image-2 分镜与产品融合

日期：2026-09-05。基线：AID 0.1.195。

状态：2026-09-05 已在本地实现角色设计入口的第一版并通过构建、模拟请求及浏览器烟测；未发布、未调用付费模型、未改动 H3。下面保留最初研究建议；实际已实现范围见本节，不把建议清单全部视为已完成。

## 本地实施结果（2026-09-05）

- 角色定稿模型独立于 Story 全局设置。MJ 使用单幅审美提示词和原生候选，不再切割独立肖像；不强制 Raw，不追加灰底/克制写实等通用模板。其他旧模型的草稿宫格流程仍保留。
- 上传原图可直接采用并入库，显示“已入库”；同名更新不重复添加。GPT 四角度延展可选，主参考始终是定稿原图。`visualMaster` 随角色库、项目保存/导出和 Series 选角保留。
- GPT 也支持单幅角色定稿。用户后来提供的历史电影提示词已抽取为可编辑的“古装电影实拍质感”预设：构图/焦点、现场光源、色彩、皮肤与材质。仅主动选择时生效，不固化样例贵妃、凤冠或 85–105mm 参数，不覆盖后续 MJ 参考。
- Story 已采用主参考时跳过自动再定妆；所选全局模型仍为 MJ 时，具有 `visualMaster` 的新角色项目用 GPT-Image-2 做四格与单镜，其他显式 GPT 通道选择保留。旧 MJ 项目不自动迁移。无人物空镜仍按场景参考/原项目设置处理。
- 有角色参考的四格/单镜移除通用摄影重塑及附加第二风格图；原图控制审美，剧本控制具体动作/景别，产品图控制产品设计。静态导演提示词增加相同边界；不修改视频指令字段、H3 模块和工作流。旧图片不会自动重做，已存旧提示词也不批量删词。
- 角色设计取消浏览器 2048px/JPEG 自动缩图。复用原始字节上传缓存：线上签名后直传存储，本地 multipart；不再把 base64 塞给线上 `/api/upload-image`。历史角色保存持久原图，不再用缩略图替代。
- 上传诊断：线上空请求 `/api/upload-image` 返回 HTML 500，签名端点真实返回 200 和合法目标（未上传图片）；证明故障在 MJ 前，具体服务器启动异常未取得日志。`sharp` 改为仅大图转换时动态加载，本机构建接口空请求为 JSON 400。不能把未发布补丁写成线上修复已验收。
- 刷新保留任务编号、已生成图和所选定稿；继续查询不重新创建任务。没有新增生成后质检或自动付费重提。
- 验证：生产构建通过；回归涵盖角色/上传/分镜/Series/H3 提示词兼容；独立浏览器 mock 通过原图采用、MJ 4 候选不拆图、GPT 单幅定稿与可选延展、入库标签、刷新恢复及手机宽度布局。模型视觉效果仍需真实小样验证，未承诺逐像素一致。

主要代码：`lib/characterVisualMaster.ts`、`app/character-design/page.tsx`、`app/api/character-design/route.ts`、`lib/storyImageRequest.ts`、`lib/gridSplitter.ts`、`lib/imageGenerator.ts`。UI 烟测：`tests/character-design-ui-smoke.mjs`（所有模型 API 被模拟）。

## 1. 推荐流程

```text
原剧本 / 选定角色 / 美术意图
              ↓
MJ 单幅人物与美术定稿 ← 用户已有 MJ 原图可直接采用，跳过生成
              ↓
固定的原始定稿图 + 本镜相关产品原图 + 原剧本的四镜动作
              ↓
GPT-Image-2 一次生成 2×2 分镜并融合产品
              ↓
已有拆图 → 现有图生视频流程（H3 采样不变）
```

核心：传递已做好的画面，而不是只传一段“像 MJ”的文字。MJ 是设计阶段，GPT 是继承设计后的镜头执行阶段。

- 定稿是带审美的单幅作品，不默认生成灰底试装照、正侧背角色表。
- 新人物可由 MJ 定稿；已有指定人物、产品、已采用的 MJ 原图不重新生成。
- GPT 的分镜和产品融合合为一次请求，不默认先出无产品分镜，再做一轮产品植入。
- 后续每批直接引用固定母版和相关产品原图，不以“上一批生成图”替代原始来源。
- 场景、服装发生真实剧情变化时，使用对应地点/服装版本，不能把一张窗边肖像的背景与机位锁死到全片。

## 3. 参考来源按职责分配，不设含糊的全局优先级

| 输入 | 决定什么 | 不决定什么 |
| --- | --- | --- |
| 角色 S1 的 MJ 定稿图 | S1 面部、妆发、服装饰品、肤质与材质观感 | 其他人的脸、每镜固定姿态和构图 |
| 项目审美母版 | 共享的电影幻想美感、色彩、光线柔硬程度、明暗过渡、景深与材质语言 | 强迫每个地点都变成母版场景；强迫未出场人物入镜 |
| 产品 P1 包装原图 | 包装色彩、版式、结构、材质、印字、真实尺度线索 | 人物审美、环境照明、膜体颜色 |
| 产品 P2 膜体原图 | 膜体颜色、孔位、网布纹理、厚薄与允许状态 | 包装设计或额外独立道具 |
| 原剧本与镜头清单 | 剧情、景别、视角、动作瞬间、表情、接触关系、产品状态 | 重设计角色/产品，添加没有要求的事件 |

同一原图可同时承担 S1 身份和审美两种职责；新模式可用一个索引列明多重职责，避免重复传图浪费容量。若 S1 不在该镜出场，母版只传递审美，不引入 S1。所有图片序号与职责文字从同一清单生成，上传后不能改变对应关系。

原图是主输入，已有的“一次性原图事实提取”只是补充标签、尺寸和物理状态；不能用文字摘要替换原图，也不对每张生成结果重复审图。

尺寸要区分真实大小和画面占比。特写时包装占画面更大是正常景别变化；手、脸与产品的真实相对比例应保持。没有尺寸证据时不编造精确厘米值；若要求完全展开的膜体且没有膜体参考，不能从金色包装猜成金色膜片。

## 4. 两层提示词

### A. MJ：人物与美术设计语言

结构：人物/气质 → 服装与饰品 → 皮肤/发丝/布料/金属质感 → 光影与色彩 → 单幅构图。只在必要时补少量输出限制；不塞四镜表、台词、产品品牌文字任务或 H3 时间轴。

按用户例子的示意正文（不是已运行结果；具体人设仍从用户选择生成）：

```text
A live-action fantasy movie still in an ancient Chinese setting. An adult
moon goddess with delicate facial features and fine realistic skin texture,
dark flowing hair, ivory fantasy hanfu with translucent flowing fabric,
intricate gold floral jewelry with red gemstones. Soft diffused studio-quality
light, gentle shadows and luminous cinematic tonal transitions. A three-quarter
close-up beside a sheer curtain, delicate strands of hair crossing her cheek,
subtle highlights on the jewelry, airy depth and an ethereal yet lifelike mood.
One finished character-and-look image, without added text or a contact sheet.
```

用户的 `life-action` 可仅做拼写修正为 `live-action`；不要以“规范化”为由改成纪实抓拍、去美化或无柔光版本。

MJ 参数独立保存：实际模型版本、raw 选择、stylize、用户启用的 profile、sref/sw、画幅，以及供应商任务编号和最终采用图片。不能仅凭图片文件名推断原样例的版本/Profile；不声称同一短提示词即可复现用户 MJ 账号中的个性化效果。已有满意原图是最直接的入口。

当前网关文档允许参数在正文或 body 传入，并注明 body 优先；因此必须防止系统 raw/version 等默认值覆盖用户有效参数。具体参数组合要以供应商回执核对，不自动换版本或盲设“最佳 stylize”。[APIMart MJ Imagine](https://docs.apimart.ai/cn/api-reference/images/midjourney/imagine)

### B. GPT-Image-2：以图片为基准的镜头执行语言

结构：任务 → 参考职责/保留项 → 四格逐镜可见瞬间 → 允许变化 → 输出布局。不复制整段 MJ 审美关键词，不重新要求生成“另一种更真实的画面”。

对应本次样例的示意请求正文（实际四格必须来自原剧本，不固定使用这四个广告动作）：

```text
基于上传的定稿原图，延展同一部唯美真人幻想电影中的四个分镜。

参考图1：角色 S1 与全片视觉母版。保持同一张脸、妆发、白色服装、
金红首饰，以及原图的肤质、发丝、白纱透光、柔和光影和景深观感。
这是已经完成的美术设计；不重新选角、换装或改变成像风格。
姿态、表情、机位和构图按下面四镜变化，不复制原图姿势。

参考图2：包装 P1 的唯一产品设计来源。保留金色袋体、形状比例、封边、
表面纹理和原有印字版式；产品接受场景里的光线，不继承参考图背景。
参考图3：膜体 P2 的唯一设计来源。保持黑灰色湿润薄膜、开孔与网布纹理；
可以按动作自然下垂、折叠，但不能变成金色硬面具。P1 和 P2 不混为一物。

左上：中近景，S1 将完整未打开的 P1 举在脸旁，一手捏住包装侧缘，
手指不遮挡主要图案；视线看向镜头，表情平静。保持人脸与包装的真实比例。
右上：包装特写，P1 正面朝镜头，手指握在两侧，S1 的侧脸位于画面边缘；
近距离展示材质和既有印字，不增加包装数量。
左下：双手近景，S1 低头看向撕口，两手拉住袋口两边，封边刚被拉开；
只表现这一瞬间，不把整个拆袋过程叠在一格中。
右下：中近景，一手握住 P1，另一手从袋口提起 P2 的上沿；黑灰色膜体自然
下垂，开孔可见，薄膜与袋口、手指的前后关系明确。

输出一张严格两行两列的 2×2 图片，阅读顺序为左上、右上、左下、右下。
整图 9:16，每格也是完整的 9:16 画面，边界位于宽高各 50%，无边框和间隙。
不添加字幕、镜号、标题或说明文案；只保留产品实物上原有的印字。
```

提示词中的“保持”是给模型的约束，不是 API 的确定性锁。自由生成无法保证面孔/包装小字逐像素不变。特别小的印字受产品实际入镜像素限制；需要读清时应在剧本镜头里给出产品近景，不靠无限加长提示词解决。

## 5. 接口与数据实现

1. 项目增加显式 `visualPipeline`，例如 `mode: mj-gpt`、`designModel: midjourney`、`storyboardModel: gpt-image-2`。保留 legacy 模式；旧项目不静默迁移。
2. 新增 `visualMaster`，与普通 `styleReference` 分离。保存源图地址、角色/服装版本、使用职责、来源 upload/MJ、实际提示词/参数和采用状态；连接角色库与项目保存/导出。
3. 新建美术定稿与分镜延展两个独立提示词编译入口。现有多轮文本导演也接收此模式，防止矛盾内容在上游先写进每镜描述。
4. UI 在现有角色与场景处增加“上传/生成定稿、采用为视觉母版”。有满意原图直接采用。提供两阶段各自的提示词预览，不再显示一个混合模型设置。
5. 批量分镜、单镜重生、自动完稿、断点恢复全部按阶段解析模型。每次付费提交前保存任务模型、母版版本、参考清单与提示词版本；刷新查询按任务快照，不按后来改变的全局设置重建。
6. 新模式绕过已指定母版的自动定妆/摄影质感评议，不为已有图再买一张。没有指定产品图的普通道具可一次建立设计并复用；用户指定产品图不能被“自动完稿”替换。
7. Story 与 Series 共用上述解析器和编译器。除了 `/story`，连续剧 runner 的公共资产生成和 production contract 也要携带模式/母版，不能只改页面按钮。

GPT 接口已支持多参考 `image_urls`，不需要新的生图服务。使用已有原图上传缓存和 URL 传输，保留图像原始细节，避免 base64 塞进请求触发原来的 413。四格是 `n:1` 的一张母图，不是 `n:4` 的四个独立候选。[APIMart GPT-Image-2](https://docs.apimart.ai/en/api-reference/images/gpt-image-2/generation)

本轮发现的文档差异：2026-09-05 实时标准通道页面为最多 15 张参考图，官方通道为 16 张；搜索缓存与本地 skill/代码仍有标准通道 16 张的旧描述。两者每图 20MB、总计 256MB 的文档上限也需按通道校准，不能只依赖现有 50MB 上传上限。按当前供应商正文配置并在提交前检查输入容量，不静默丢图。此处是传输验证，不是生成后视觉质检。[标准通道](https://docs.apimart.ai/en/api-reference/images/gpt-image-2/generation)、[官方通道](https://docs.apimart.ai/en/api-reference/images/gpt-image-2/official)

默认沿用 `gpt-image-2`，不擅自切官方通道或开启官方回退。只有用户选择官方通道才按其文档设置 `quality=high`；不能把该参数或数值型“参考权重”当成标准通道保证支持的能力。参考职责主要通过提示词表达，文档未提供每张图的语义锁开关。

继续使用 9:16 / 16:9 的 4K 四格母图；以 2160×3840 为例，每格切割前为 1080×1920，不是每格 4K。最终尺寸以真实输出为准，不改变本轮拆图代码或承诺分辨率等于细节保真。

## 6. 实施顺序与边界

建议先接“已有 MJ 原图 → GPT 四格”的最小闭环，再在同一视觉母版结构下接系统内 MJ 定稿生成。前一步直接复用本次用户满意原图，能隔离“MJ 能否复现审美”和“GPT 能否继承审美”两个问题；不把两类变化一起引入。

实施时的软件验收应覆盖：分阶段模型解析、两套提示词无相反规则、每批原图/产品绑定完整、多人不串脸来源、已有资产不重做、保存/导出恢复、切换项目隔离、老付费任务续查不重提。均可先用模拟请求检查；不是给用户每次生产增加质检。

真实效果验证仅在另外明确授权生成后，用本次 MJ 原图、独立包装/膜体参考和固定四镜做少量人工选型对比；不开展自动逐帧审查或失败后无限重买。用户提供的 GPT 示例能支持方案值得做，但示例未给出可核验的 API 通道/完整请求参数，不能宣称 APIMart 已复现完全同样效果。

不做：H3 采样升级、LoRA/显存改动、所有镜头串行、每镜重新 MJ 定稿、默认双轮产品植入、图像评分系统、自动重做旧项目。保留原剧本的剧情、动作和对白；生图只取相应动作瞬间，完整对白仍放在既有独立语音数据中。
