# 连续剧制片工作台

入口：`/series`，首页「连续剧制片」。这是一个独立模块；普通 Story 的项目、自动运行标记和 API 设置不被连续剧执行器覆盖。

导航顺序为「故事总纲 → 角色与场景 → 分集故事 → 制作队列 → 成片」，打开或切换连续剧时默认进入故事总纲。

## 使用流程

1. 新建连续剧：填写创意、题材、1–100集、画幅和画风，单集短片可直接把计划集数设为1。普通故事创意默认每集16镜、目标约120秒，新建与改写的镜头数按4的倍数规划。若粘贴包含连续“镜1、镜2……”且写明动作/运镜/生图提示词或台词的成稿，系统自动按一集权威成稿处理，保留原镜头数。创建项目本身不请求模型。
2. 开发总纲与分集故事：先建立总纲、角色和场景，随后每次展开1集、校验后立即保存。可以在列表直接查看每集回报、结尾钩子与制作状态。
3. 角色与场景定稿：总纲与角色、场景清单已保存即可独立执行，无需等待分集全部完成；如果分集编剧失败，页面会展示原因，已保存的资产仍可定稿。使用「自动完成定稿」一次准备全剧公共资产，也可在单个角色上点击「生成这张角色卡」，只排队生成该角色形象，不连带生成其他角色、声音、场景或道具。已完成角色可点击「加入 / 更新角色库」，把角色卡及已定音色保存到当前浏览器，以后从角色库一键选用。支持手动填写角色参考图HTTPS地址与Fish音色ID。

全剧固定道具分为两种参考来源：总纲自动识别出的关键道具默认由系统在资产定稿时生成独立参考图；品牌商品、指定包装或已有实物应选择「我指定参考图」并上传图片，系统不会重画该来源。手动新增道具即表示需要写入剧情：保存后自动从第1集开始重写分集故事，由模型选择最合适的集数让道具承担具体行动、阻力、线索或回报，再由这些分集要求详细分镜实际呈现。不会机械塞入每一集；旧成片作为历史版本保留。成型原稿只允许追加简短可见道具互动，不能替换原动作、生图提示词、台词、镜头边界或顺序。此能力要求 Companion v0.1.179 或更新版本。

从 Companion v0.1.150 起，单集生产会在导演前自动同步已保存合同与当前角色卡的音色，并把已登记的台词说话者补回对应镜头角色列表；不会改写台词。T8 的三个音色参考与台词轮次分开计数，同一至三个角色可完成最多六轮短对答。导演若误把 `videoDirection` 动作写成中文，会按最多四个字段一批保存局部英文修稿并继续断点恢复；被拒绝的截句原因会反馈给下一轮，避免重复提交同一个坏补丁。
4. 展开镜头：单集或批量生成。普通故事默认按16镜展开，并按每4镜一组生成2×2四宫格；成稿采用原稿实际镜头数，末批可少于4镜。所有后续预检和生产合同均按项目当前镜头数验收。成稿逐镜映射角色、场景和道具ID，原动作、景别、运镜、氛围、AI生图提示词、台词及顺序不可改写；只有用户后来手动新增的剧情道具可以最小增补。原时长说不完逐字台词时只延长时长，不删台词。公共资产尚未定稿时先进入全剧资产定稿，再按最终登记反向校正ID。可查看、编辑结构化剧本、导出Markdown。
5. 单集成片或一键成片：按「准备最终资产 → 反向校正镜头剧本 → 进入Story分镜与成片」的顺序自动执行。旧版曾把成稿扩写成固定镜数的项目会在下次队列重试时保留资产和历史交付、撤销扩写，并按原镜号与动作重制。已交付当前版本的集数跳过；同一任务不会重复入队。建议先制作第一集检验真实效果。
6. 成片页面：按集预览、独立下载MP4，也可下载旧版。制作档案可导出JSON（不包含供应商密钥）。下载不等于发布，没有自动发布到外部平台的功能。

## 删除与恢复（v0.1.106）

剧名右侧的「删除连续剧」会要求二次确认，再将整部剧移入左栏「回收站」。总纲、剧本、角色场景、任务记录和历史成片仍保留在本机，不改写原角色库和普通Story项目。回收站不是清理磁盘功能，不会删除素材文件。

如果还有执行中的任务，请先暂停队列，等待任务保存断点后再删除。删除会原子暂停待执行任务；回收站里的项目不接受编辑、重试和制作请求。恢复会把项目放回列表，但队列仍保持暂停，必须主动继续或重试才会执行。旧页面或过期执行器不能继续写入已删除的剧。

删除和恢复都需要Companion v0.1.106或更新版本。测试脚本 `scripts/series-trash-smoke.mjs` 只可对新建、空白、隔离的本机测试数据目录运行。

## 编剧与连续性

- v0.1.189 起，角色入库保留登记别名及选角名，Story 编剧、旧剧本加载和导演阶段按登记关系统一人物与说话人 ID；原稿多轮对答仍使用同一人物，不改原句或顺序，也不凭姓名相似合并不同角色。分行原分镜的动作与运镜会一起进入整理流程。
- 原稿已有完整镜头、尾部却出现未带供应商明确拒绝标记的中断文字时，Companion 仅自动补齐一次缺失镜头，已完成镜头不重写。原稿、补镜结果、停止原因与已尝试标记保存到本地，刷新或重启不重复购买。明确的供应商审核拒绝仍停止；无法补齐时查看错误后人工处理。
- 总纲保存持续冲突机制、世界规则、终局、阶段故事、伏笔和计划回收集数。
- 分集保存目标、阻力、主动选择、局部回报、钩子、下集承接、事件变化与人物知情变化。
- 写当前集时提供相关角色/场景、近期故事、已发生事实与知情记录，不重复输入历史完整镜头与媒体数据。
- 结构化校验要求阶段覆盖整季、人物/场景/伏笔引用有效、伏笔按计划回收。普通故事当前默认16镜，单镜2–15秒，总计115–125秒；权威成稿严格保持原镜头数，生产全程读取项目实际 `shotCount`。台词超出原时长时只增加该镜时间，单镜仍不超过15秒。
- 资产定稿后的反向校正以最终角色和固定道具登记为准：发声角色漏挂在本镜时直接安全补齐。普通生成剧本中“道具ID已标记但画面未使用正名/别名”的问题会一次收集并定点修复；权威成稿则保留“黑色面膜”等原始自然说法，由结构化 `objectIds` 绑定最终道具参考，不为凑正名改写原动作或生图提示词。普通故事的镜头数量偏差可归并/拆分到项目指定的4的倍数，但任何原台词不得增删、改写或调序，固定道具线索不得提前删除。
- 每次自动反向校正会保存在分集记录中，并在分镜详情顶部显示修正数量与内容。该流程约束资产引用和结构，不会借机重写已经正确的剧情。
- 用户修改分集会生成新版本，保存用户修改字段，标记本集和后续集数需要重新核对。点击「更新分集故事」后重新推导知情状态与承接；模型不能静默撤销用户修订。
- Story二次编排在进入画面制作前检查镜头数、发声角色、声音绑定和逐字台词。遗漏、重复、擅自改写或新增发声角色会停止该集。
- 这些检查约束结构和连续性，不保证故事一定吸引观众，也不等同于自动审美评价。

## 自动选声

### 从已有角色库选角（v0.1.103）

进入「角色与场景」，点击任意主角或配角的「从角色库选角」。列表读取当前浏览器中的角色设计记录和Story历史角色，支持按名字或外形搜索。选定后由该库内演员出演剧中角色，剧中名字、身份、人物关系和故事不变。

- v0.1.105保留完整卡、原库概念图及同名历史图片；某地址无法加载时尝试其他已存图片，选用时仅保存实际加载成功的图片。全部无法加载时明确提示并阻止误选，可刷新重试；不会删除或改写原角色库。
- 完整角色卡优先复用；旧角色只有参考形象时也直接采用，不重新生图。库记录以快照保存在连续剧中，之后修改原角色库不会悄悄改变本剧。
- 库内有音色ID则继承，缺少试音时仅补齐试音。库内无音色时，保留剧中单独指定的音色；之前由另一位库内演员带来的音色不会误用，未指定部分自动匹配。
- 换角保留镜头剧本及旧版成片，只清除出场剧集的制作断点并创建新版本。重复选择同一个演员保留已经完成的准备工作。
- 手动修改外形或参考图会解除角色库形象绑定，重新走定稿流程。
- 历史角色的本地图片会在选用时经现有图床保存为HTTPS地址；不上传整个角色库，也不请求AI重新生图。
- 角色库保存在浏览器本地，不同浏览器及localhost/正式域名互不共享。列表为空时，请使用原来保存角色的浏览器和站点，或在当前站点的角色设计中保存角色。

### 自动匹配与锁定

用户明确指定的音色优先。未指定时搜索Fish自有工作区（包括私有模型）和`licensed=true`的平台授权库，每类最多5页，每页100条。自有模型标明工作区来源，不冒充平台授权认证；用户应确保有使用权。原语言匹配优先，不足时将跨语言候选交给试读验证；排除已知性别冲突、已占用、下架、正在退役的声音，保留最多3个。无结果会说明搜索范围和筛选条件，不因公开可访问就视为已授权。

角色卡的「从 Fish 音色库选声」可直接浏览 Fish 公共库，也可切换平台授权库和工作区。搜索框默认空白，剧情角色名只用于展示待配音对象，不作为音色名称查询。现有样本试听不发起新合成；公共/工作区选择需确认使用权，选定后固定 ID，并在下次定稿时试读、验证目标语言。声音变更保留角色图片和历史成片，已生成的相关分集制作断点会失效。

自动音色不足会记录角色 `voiceIssue`，继续准备其他角色与场景；素材准备后汇总待选声音，完成选声后从断点重试。未选择的角色不会被当作声音就绪，也不会自动复用其他角色的音色。服务、鉴权和存储异常仍立即停止。

系统从排名最高的候选开始合成标准试读，仅明确的音色不可用才尝试下一个；存储、账户、额度和网络问题停止，避免无效消耗。成功后保存实际音色ID、来源、试读地址、匹配原因与独立锁定状态。所有后续集数复用，不把“自动来源”误当成“可以重新选角”。生成试读严格使用选定ID，不静默切换。

当前版本是**资料匹配 + 合成可用性检查**，尚未接入能可靠比较演技、情绪或声音相似度的音频评价模型，也不会宣称已经试听比较所有候选的表演。没有合适授权候选时明确报错，可修改声音简报或指定已有授权音色；不随机回退到来源不明的声音。

官方依据（2026-08-30核对）：

- https://docs.fish.audio/api-reference/endpoint/model/list-models
- https://docs.fish.audio/developer-guide/sdk-guide/cookbook/discover-library-voice

## 队列与后台执行

队列、项目版本与成片保存到Companion数据目录下的`series/`。开发环境未设置`AID_COMPANION_DATA_DIR`时使用`~/.aid-companion/series`。模型配置在队列中加密保存，本地密钥文件与数据库权限为0600；项目列表和导出不返回配置或租约凭据。加密不替代操作系统账户保护。

- 新版Electron Companion启动独立的沙箱执行窗口，后台托管现有浏览器版Story引擎；关闭网页或隐藏Companion窗口不结束制作。仍需保持Companion运行、电脑唤醒与网络可用。
- `npm run dev` / 单独Next服务没有Electron后台窗口，页面会挂载备用执行器；此模式必须保持页面打开。界面按实际执行器模式提示。
- 服务端租约防止两个页面或Companion同时执行同一队列。每5秒心跳；租约45秒失联后可恢复，连续启动中断3次后停止并提示检查。
- 主动暂停等待保存断点；已经提交给供应商的任务不会因此自动取消。恢复优先查询已保存的任务编号。
- 某集失败不阻止其他独立集数继续。失败任务可从断点重试。没有自动提高额度、购买余额或无限重试。
- 当前任务和历史记录中的失败任务均可点击「删除任务」。仅删除该条任务记录及其保存的配置，不删除剧本、制作断点、素材或成片；刷新后不会恢复。排队、执行、暂停和已完成任务不能通过此入口删除。需要支持任务删除的新版 Companion，旧版本会提示更新。
- 单集成片保存时检查有效视频轨道、声音轨道、画幅和可读取的正数时长，不再把“约2分钟”解释成90–150秒的硬性区间。导出器仍会按实际片段时间线校验成片没有截断；支持HTTP Range播放，文件写入完成前不标记交付成功。
- 数据库仅在本机开发服务/Companion启用，托管站点需要连接Companion，不使用共享服务器目录保存不同用户的项目。

连续剧基础功能需要Companion v0.1.102或更新版本；资产定稿后反向校正剧本需要 v0.1.175 或更新版本；不限于两分钟的成片保存需要 v0.1.180 或更新版本。旧安装包不会因为网页更新自动获得新执行器，请从AID首页下载新版；关闭网页继续运行仍需保持Companion开启。

从 Companion v0.1.177 起，H3 中文逐字台词在生成提示词中明确只属于音轨和口型，画面末尾约束禁止显示中文字幕、对话字形及拼音/音译行；不增加字幕 OCR、字幕质检或后处理去字幕步骤。新提示词使用 `h3-v37`，旧合同生成的视频片段会按需重制。

## 故障恢复（v0.1.107）

- Companion无本地Cloudinary配置时，由网站签发限制目录、禁止覆盖的临时上传签名，媒体直接上传Cloudinary，不经过网站大文件请求体；云存储Secret仍留在网站。图片、音频、网格图和视频共用此通道。签名接口与现有上传接口沿用同一访问边界，不接收Fish/编剧密钥，禁止任意目录与管理操作。
- 试读提交前检查保存通道；合成成功后将音频保存在`voice-reference-cache/`，上传失败只补上传，服务重启后仍可恢复，并合并同一音色的并发请求。缓存按账户、音色、语言、严格匹配和试读文本区分，不存API密钥。云端临时文件系统缓存只在实例存续期间有效，跨重启持久化由本地Companion提供。
- 原始编剧回复先保存到`series-drafts/`，每集按明确的埋设/回收清单校验。失败时携带原稿与校验错误定向修稿，最多3次模型调用；仍未通过时保留原稿，下次接着修，不放宽伏笔规则、不用程序硬塞ID。原稿中的故事质量仍需人工审阅。
- 已通过分集立即写入项目；后续集失败不会抹掉先前进度。原稿缓存也可在响应或项目检查点丢失后复用。
- 旧版本失败且未保存的供应商响应无法凭空恢复；断电/磁盘故障发生在供应商成功与本地落盘之间仍可能丢失结果。网络超时不被视为音色不合适，不自动切换候选。缓存随本地数据备份，暂不自动清理。
- 新增回归测试覆盖保存前检查、上传失败重启恢复、并发去重、逐集断点、p4修稿原文、未通过校验拒收、自有音色筛选，以及大文件直接上传。

上传签名官方依据：https://cloudinary.com/documentation/authentication_signatures

## 跨语言选声与任务历史（v0.1.108）

- Fish音色条目的`languages`是原始参考语言，不代表S2只能说这些语言。原语言匹配优先；不足3个候选时扩大到全语言的平台授权库和自有工作区。仍排除已占用、已知性别冲突、不可用或下架模型；不把普通公共音色冒充授权音色。
- 跨语言候选必须先使用本剧语言合成标准短试读，再通过Fish ASR自动识别实际语言，并与固定试读文本比较。检测到其他语言或文字匹配低于70%时换下一个候选；这不是演技或口音评分。
- 验证结果随音频保存。ASR网络、额度或账户故障只阻止验证，不丢弃音频、不换声再合成；重试只补验证。旧版缓存也可补校验，并发的新旧请求不会跳过校验。
- 队列默认展示各阶段当前任务，旧的已结束任务折叠到「历史任务记录」，显示时间并保留原错误；历史记录不提供重复重试按钮。服务端也拒绝历史任务重试及同阶段重复排队，保护旧页面用户。
- 真实验证：本次He Jin采用平台授权候选完成约9秒英语试读，ASR语言为en，标准文本匹配100%，结果缓存于本地。其余缺声角色已有互不重复的候选，但未宣称全部通过试音。未启动图片、视频或整季编剧。
