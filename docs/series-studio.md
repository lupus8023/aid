# 连续剧制片工作台

入口：`/series`，首页「连续剧制片」。这是一个独立模块；普通 Story 的项目、自动运行标记和 API 设置不被连续剧执行器覆盖。

导航顺序为「故事总纲 → 角色与场景 → 分集故事 → 制作队列 → 成片」，打开或切换连续剧时默认进入故事总纲。

## 使用流程

1. 新建连续剧：填写创意、题材、2–100集、画幅和画风。每集固定18镜，目标约120秒。创建项目本身不请求模型。
2. 开发总纲与分集故事：先建立总纲、角色和场景，随后每次展开1集、校验后立即保存。可以在列表直接查看每集回报、结尾钩子与制作状态。
3. 角色与场景定稿：总纲与角色、场景清单已保存即可独立执行，无需等待分集全部完成；如果分集编剧失败，页面会展示原因，已保存的资产仍可定稿。此能力要求Companion v0.1.105或更新版本。使用「自动完成定稿」一次准备全剧公共资产；也可以直接制作单集，系统仅补齐该集所需资产。支持手动填写角色参考图HTTPS地址与Fish音色ID。
4. 展开18镜：单集或批量生成。镜头包含时间、人物、场景、行动、逐字台词、声音和叙事作用。可查看、编辑结构化剧本、导出Markdown。
5. 单集成片或一键成片：按顺序调用现有Story引擎。已交付当前版本的集数跳过；同一任务不会重复入队。建议先制作第一集检验真实效果。
6. 成片页面：按集预览、独立下载MP4，也可下载旧版。制作档案可导出JSON（不包含供应商密钥）。下载不等于发布，没有自动发布到外部平台的功能。

## 删除与恢复（v0.1.106）

剧名右侧的「删除连续剧」会要求二次确认，再将整部剧移入左栏「回收站」。总纲、剧本、角色场景、任务记录和历史成片仍保留在本机，不改写原角色库和普通Story项目。回收站不是清理磁盘功能，不会删除素材文件。

如果还有执行中的任务，请先暂停队列，等待任务保存断点后再删除。删除会原子暂停待执行任务；回收站里的项目不接受编辑、重试和制作请求。恢复会把项目放回列表，但队列仍保持暂停，必须主动继续或重试才会执行。旧页面或过期执行器不能继续写入已删除的剧。

删除和恢复都需要Companion v0.1.106或更新版本。测试脚本 `scripts/series-trash-smoke.mjs` 只可对新建、空白、隔离的本机测试数据目录运行。

## 编剧与连续性

- 总纲保存持续冲突机制、世界规则、终局、阶段故事、伏笔和计划回收集数。
- 分集保存目标、阻力、主动选择、局部回报、钩子、下集承接、事件变化与人物知情变化。
- 写当前集时提供相关角色/场景、近期故事、已发生事实与知情记录，不重复输入历史完整镜头与媒体数据。
- 结构化校验要求阶段覆盖整季、人物/场景/伏笔引用有效、伏笔按计划回收。镜头严格18个，单镜2–15秒，总计115–125秒，台词须留出表演时间。
- 用户修改分集会生成新版本，保存用户修改字段，标记本集和后续集数需要重新核对。点击「更新分集故事」后重新推导知情状态与承接；模型不能静默撤销用户修订。
- Story二次编排在进入画面制作前检查镜头数、发声角色、声音绑定和逐字台词。遗漏、重复、擅自改写或新增发声角色会停止该集。
- 这些检查约束结构和连续性，不保证故事一定吸引观众，也不等同于自动审美评价。

## 自动选声

### 从已有角色库选角（v0.1.103）

进入「角色与场景」，点击任意主角或配角的「从角色库选角」。列表读取当前浏览器中的角色设计记录和Story历史角色，支持按名字或外形搜索。选定后由该库内演员出演剧中角色，剧中名字、身份、人物关系和故事不变。

- v0.1.105保留完整卡、原库概念图及同名历史图片；某地址无法加载时尝试其他已存图片，选用时仅保存实际加载成功的图片。全部无法加载时明确提示并阻止误选，可刷新重试；不会删除或改写原角色库。
- 完整角色卡优先复用；旧角色只有参考形象时也直接采用，不重新生图。库记录以快照保存在连续剧中，之后修改原角色库不会悄悄改变本剧。
- 库内有音色ID则继承，缺少试音时仅补齐试音。库内无音色时，保留剧中单独指定的音色；之前由另一位库内演员带来的音色不会误用，未指定部分自动匹配。
- 换角保留镜头剧本及旧版成片，只清除出场剧集的制作断点并创建新版本。重复选择同一个演员保留已经完成的准备工作。
- 手动修改外形或参考图会解除角色库形象绑定，重新走定稿流程。
- 历史角色的本地图片会在选用时经现有图床保存为HTTPS地址；不上传整个角色库，也不请求AI重新生图。
- 角色库保存在浏览器本地，不同浏览器及localhost/正式域名互不共享。列表为空时，请使用原来保存角色的浏览器和站点，或在当前站点的角色设计中保存角色。

### 自动匹配与锁定

用户明确指定的音色优先。未指定时搜索Fish自有工作区（包括私有模型）和`licensed=true`的平台授权库，每类最多5页，每页100条。自有模型标明工作区来源，不冒充平台授权认证；用户应确保有使用权。按语言与声音简报匹配，排除语言未知/不符、性别冲突、已占用、下架、正在退役的声音，保留最多3个。无结果会说明搜索范围和筛选条件，不因公开可访问就视为已授权。

系统从排名最高的候选开始合成标准试读，仅明确的音色不可用才尝试下一个；存储、账户、额度和网络问题停止，避免无效消耗。成功后保存实际音色ID、来源、试读地址、匹配原因与独立锁定状态。所有后续集数复用，不把“自动来源”误当成“可以重新选角”。生成试读严格使用选定ID，不静默切换。

当前版本是**资料匹配 + 合成可用性检查**，尚未接入能可靠比较演技、情绪或声音相似度的音频评价模型，也不会宣称已经试听比较所有候选的表演。没有合适授权候选时明确报错，可修改声音简报或指定已有授权音色；不随机回退到来源不明的声音。

官方依据（2026-08-30核对）：

- https://docs.fish.audio/api-reference/endpoint/model/list-models
- https://docs.fish.audio/developer-guide/sdk-guide/cookbook/discover-library-voice

## 队列与后台执行

队列、项目版本与成片保存到Companion数据目录下的`series/`。开发环境未设置`AID_COMPANION_DATA_DIR`时使用`~/.aid-companion/series`。模型配置在队列中加密保存，本地密钥文件与数据库权限为0600；项目列表和导出不返回配置或租约凭据。加密不替代操作系统账户保护。

- 新版Electron Companion启动独立的沙箱执行窗口，后台托管现有浏览器版Story引擎；关闭网页或隐藏Companion窗口不结束制作。仍需保持Companion运行、电脑唤醒与网络可用。
- `npm run dev` / 单独Next服务没有Electron后台窗口，页面会挂载备用执行器；此模式必须保持页面打开。界面按实际执行器模式提示。
- 服务端租约防止两个页面或Companion同时执行同一队列。每5秒心跳；租约45秒失联后可恢复，连续启动中断3次后停止并提示检查。
- 主动暂停等待保存断点；已经提交给供应商的任务不会因此自动取消。恢复优先查询已保存的任务编号。
- 某集失败不阻止其他独立集数继续。失败任务可从断点重试。没有自动提高额度、购买余额或无限重试。
- 单集成片保存时检查有效视频轨道、声音轨道、画幅和90–150秒的交付时长。支持HTTP Range播放；文件写入完成前不标记交付成功。
- 数据库仅在本机开发服务/Companion启用，托管站点需要连接Companion，不使用共享服务器目录保存不同用户的项目。

连续剧需要Companion v0.1.102或更新版本。旧安装包不会因为网页更新自动获得新执行器，请从AID首页下载新版；关闭网页继续运行仍需保持Companion开启。

## 验证

```sh
npm run test:series
npx tsc --noEmit
npm run build:companion
```

API冒烟测试只应对**隔离数据目录的本机开发服务**运行，会创建明确标注的测试项目和编码测试视频，不请求任何模型：

```sh
# 先指定独立AID_COMPANION_DATA_DIR，以及本机FFPROBE_PATH和FFMPEG_PATH，再启动开发服务。
npm run dev -- --port 3027
npm run test:series-api -- http://localhost:3027
```

测试覆盖脚本规范、伏笔回收、知情上下文、声线锁定、定稿台词、项目隔离、并发存储、凭据隐藏、排队去重、暂停恢复、版本冲突、真实媒体探测、下载与旧版保留。运行器测试使用受控供应商/Story响应，不产生付费素材。

本次没有提交真实Fish试音或AI视频生成，因此角色审美、最终声音一致性、供应商实际时延与整季成本仍需用实际样片验证。第一版尚无货币金额预算预估、自动演技评分、复杂服装变体排期或整季合并导出。

## 故障恢复（v0.1.107）

- Companion无本地Cloudinary配置时，由网站签发限制目录、禁止覆盖的临时上传签名，媒体直接上传Cloudinary，不经过网站大文件请求体；云存储Secret仍留在网站。图片、音频、网格图和视频共用此通道。签名接口与现有上传接口沿用同一访问边界，不接收Fish/编剧密钥，禁止任意目录与管理操作。
- 试读提交前检查保存通道；合成成功后将音频保存在`voice-reference-cache/`，上传失败只补上传，服务重启后仍可恢复，并合并同一音色的并发请求。缓存按账户、音色、语言、严格匹配和试读文本区分，不存API密钥。云端临时文件系统缓存只在实例存续期间有效，跨重启持久化由本地Companion提供。
- 原始编剧回复先保存到`series-drafts/`，每集按明确的埋设/回收清单校验。失败时携带原稿与校验错误定向修稿，最多3次模型调用；仍未通过时保留原稿，下次接着修，不放宽伏笔规则、不用程序硬塞ID。原稿中的故事质量仍需人工审阅。
- 已通过分集立即写入项目；后续集失败不会抹掉先前进度。原稿缓存也可在响应或项目检查点丢失后复用。
- 旧版本失败且未保存的供应商响应无法凭空恢复；断电/磁盘故障发生在供应商成功与本地落盘之间仍可能丢失结果。网络超时不被视为音色不合适，不自动切换候选。缓存随本地数据备份，暂不自动清理。
- 新增回归测试覆盖保存前检查、上传失败重启恢复、并发去重、逐集断点、p4修稿原文、未通过校验拒收、自有音色筛选，以及大文件直接上传。

上传签名官方依据：https://cloudinary.com/documentation/authentication_signatures
