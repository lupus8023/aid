# DaSiWa 配对与 H3 提示词技能适配（2026-09-07）

## 已确认的配置错误

0.1.200 的普通图生视频、Story、连续剧和 Director 使用了 FL2VA pruned 基座与一个只为 DaSiWa 指定权重投影的四步 LoRA。此前少量样片能运行，不代表这个组合兼容。本页替代此前文档中把这组搭配作为通用生产方案的结论。

云端文件的 safetensors 元数据和实际 SHA-256 已核对：

| 项目 | 正确配对 |
| --- | --- |
| 基座 | `DasiwaMinimaxH3_dasiwaREF2VAHybridV1.safetensors` |
| 基座 SHA-256 | `71c61492faf65b410d0726840ac3b27b017fcfeb76b16ae11589223d81b7121c` |
| LoRA | `minimax_h3_turbo_4step_dasiwa_ref2va_hybrid_v1_T8.safetensors` |
| LoRA SHA-256 | `d2a9a723d97520232f17b6fec33335f9e94b03b2c67b56f91f16780355479274` |
| LoRA 兼容范围 | `exact_checkpoint_sha256_only`，目标即上面的基座哈希 |
| 采样 | Bypass LoRA，强度 1，T8 四步，video/audio shift 12/3，dual_clock_euler/simple |

DaSiWa 文件元数据标题明确含 `hybrid_pruned_int8_convrot`，所以仍采用用户选定的 pruned＋4 步。I2VA、FL2VA、Ref2VA 是输入条件模式，不能据此把专用适配器改挂到另一份权重。Director 保留自身 Euler 采样接口与连续上下文实现，模型配对引用同一份配置。

用户提供的 [Tensor.Art 模型页](https://tensor.art/models/1035601270213216816) 对应 DaSiWa REF2VA Hybrid；该页同时列出其他 Turbo 版本，不能仅凭 DaSiWa 名字混用。对当前投影 LoRA，实际嵌入的目标文件哈希是配对依据。

## 官方技能如何融入

已安装 [官方 h3-prompt-writing](https://github.com/MiniMax-AI/MiniMax-H3/tree/main/skills/h3-prompt-writing) 至 `/Users/yao/.codex/skills/h3-prompt-writing`（核对上游 HEAD `d21241f0a4b3acbb34c97dae47fa417b7065e438`），阅读 `SKILL.md` 和 `references/base-en.txt`、`references/ref-en.txt`。它提供编写规则，不提供生成模型或公开版 Context-IR 服务。

适配落实在公共提示词编译器，而不是要求用户手动调用技能：

1. 单图且没有额外音色/实物参考时使用首帧对齐说明加三个字段：`integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。不再把这类镜头伪装成全参考任务。
2. 带角色音色或其他参考的任务使用六字段，并区分 `keyframe completion` 和 `audio reference`。音频仅提供音色，不复制其原台词；原剧本 `<d>` 逐字保留。
3. 保留具体道具词。没有独立道具参考图时，白玉杯、木盒等原名不再被一律抹成“已引用物体”。真正附带参考图的对象继续使用现有 T8 绑定约定。
4. 首镜不再附加一个伪切镜时间区间；摄影说明保留运动类型、方向、幅度、速度、触发和落点。导演合同补充实际运动边界、留画范围和停止条件（见下文对照）。去掉公共镜尾指令中与导演运动冲突的“保持当前构图到结束”。
5. 视觉修正、系列风格、全片结尾约束插入相应的视觉正文，不落到音乐字段之后。
6. 新提示词合同为 h3-v42；保持兼容旧的、创作输入没变的付费视频。

项目适配边界：官方原文建议英文正文；本项目继续保留既有中文导演要求及原语言对白，不默默切回英文。四步模型参数与分镜时长不由这份提示词技能改写，也不把技能示例的切镜或抖动手法复制进每个单镜头。

## 新反例与结论边界

原故障实际首帧为 `144113eee5103133e3bf688900a5b89a4f6fc5a096adb0b021685e542371e971.webp`，862×1532；整集当前存档下载到的首帧为 `dbe4b0d4bb2695096ff82320e3422d1428bc02648e40ed57ef437fa92d213d62.jpg`，862×1600。因此不能把整集第 1 镜和原故障当成同图同种子对照。上面的基座单变量对照确实保留了原 WebP，依然有效。

进一步以原 WebP、原精确种子、正确配对，**只替换官方格式候选提示词**，得到 `f18ede7d-ed39-46a0-ac1a-bbdb805fb075`（`original-seed-guide.mp4`）。约 4 秒后仍长出蓝色额头纹理。说明正确配对和官方结构均不足以保证消除该缺陷；LoRA 元数据中的 `static_projection_validated; perceptual_render_pending` 也不能当作感知质量验收。运动分析 P95 为 4.986、median 为 1.729，仍仅是筛查指标。

保留正确权重兼容修复，不把新结构作为纹理/字幕修复宣称。另以该失败结果为基线，仅将 video shift 12 改为 6，提交 `95a1f0dd-7d82-4cf8-8487-4f8ee1db9c3a`；实验已完成：纹理扩大，运动变化 P95 为 17.745、median 为 6.341，明显劣于该失败基线；该方案不采用，默认仍为 12/3。再仅替换相机段落，限定原机位高度/焦距、主体完整中景和遮挡解除即停止，提交 `34987e63-6d34-4f3d-be82-ff928a10b5aa`。该对照完成，半秒抽帧未见蓝色额头纹理，运动变化 P95 降至 1.164、median 0.396；手部动作仍有偏离。两对照的完整 history 差异经脚本断言，只改变所声明的参数/相机文字和输出前缀。相机路径不同，指标不能转换为通用“抖动减少百分比”。

据此在 `videoDirectionWritingContract` 补充运动中的留画范围和可观察停止条件；仅横移揭示关系时交代高度/焦距保持，剧情确需变化则明确变化与落点。不强制每镜固定机位，也不要求所有演员全身始终入画。不自动重写已批准导演稿或作废付费视频。候选控制只支持该镜有改善，未替换整集已保存的第 1 镜。

## 旧导演稿的提交前保护

独立测试最初直接调用视频接口，遗漏前端正常会执行的导演稿细化。第 5 镜起存档的 `videoDirectionSource` 与当前分镜不匹配，编译器退回通用动作段落；第 9 镜生成画面甚至出现了该段落中的“不作展示姿势”。这些镜头不能充作完整生产流程的验收样本，已停止这轮测试继续提交。

正式复测放在 `episode1-reviewed/`：复用导演稿有效的前四镜，其余镜头先调用同款 `generate-video-prompt` 细化、保存并校验导演稿，再调用 `generate-video`。原失败流程的媒体和回执保留作证据，不覆盖生产数据库。

视频接口增加提交前检查：没有有效导演稿、也没有明确编辑的完整提示词时，返回 `VIDEO_DIRECTION_STALE`，在提交 GPU 前停止。正常 Story/连续剧的提示词细化步骤保持；不会悄悄用通用模板买一条视频，也不会在提交接口内隐形重写导演稿。该保护与字幕概率根治不是同一件事。
