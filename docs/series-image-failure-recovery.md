# 连续剧图像任务的失败恢复

`prepareSeriesImage` 共用于角色卡、GPT定妆主图和场景准备。状态查询是 HTTP 200 并不代表生图成功。`readApiJson(..., { taskStatus: true })` 仅在非流式任务查询中保留 `{status:'failed', error}`，其他响应仍按错误处理。

- 明确终态临时失败：保留历史，最多三次生成，恢复执行器不能重置预算。
- 查询断连：继续查询同一任务；连续六次失败时保存待查询状态，不重新提交。
- 已生成但存储失败：最多三次重新保存；断点恢复仍使用原任务。
- 提交结果不明确：保留未确认状态，不自动发起另一次付费请求。
- DNS 解析失败或明确发生在 TLS 建连前的断开：HTTP 请求尚未发出，GPT 生图提交最多自动重连三次，中间尝试现有公共 DNS 连接器。禁止将普通 ECONNRESET、超时、HTTP 错误或重定向后的断连当成未提交。
- 三次建连均失败：服务端提交回执保存 `not_sent` 和未发送原因。同一个提交编号可在断点恢复时通过排他锁重新连接；一旦可能已发出请求又丢失响应，立即回到 `uncertain`，不能重复购买。旧的 `uncertain` 回执缺少证明时绝不自动改成未提交。
- 上游内容审核拒绝：保存原因和任务编号，只阻塞相关素材。后续从断点重试只查询原任务；只有供应商返回 completed 和结果图片后才恢复，查询失败或 pending 不清除拒绝记录。Story、连续剧准备和自动重试均识别中文及英文拒绝，不关闭审核、不自动改写被拒请求、不换通道重提。
- 用户修改角色外形/参考图或主动改选角色库演员时，清除旧图像准备状态，避免旧任务错误附着到新的资产。纯声音修改不清除图像状态。

公共资产准备继续处理独立素材，最后汇总未完成项；必需素材缺失时不得进入成片或宣称完成。界面必须区分原始参考图、本轮角色卡、上游拒绝。重试入队清除旧的结束时间。

回归覆盖：`tests/api-response.test.mjs`、`tests/series-image-preparation.test.mjs`、`tests/series-runner.test.mjs`、`tests/image-prompt-safety.test.mjs`、`tests/auto-production.test.mjs`。2026-08-31真实MJ测试还验证了重启及重试没有新增提交；外部审核拒绝本身尚未解决，不能把本地测试通过等同于完整影片通过。

2026-09-01 整季 GPT 重制中，两个场景遇到 Node 明确报告的 TLS 建连前断连。修复和费用保护回归见 `tests/image-connection-recovery.test.mjs`、`tests/series-image-submission.test.mjs`。日志仅记录已脱敏的错误摘要，不记录 Axios 配置或 Authorization。
