# 本地成片导出的并发与缓存恢复

2026-09-01《珍珠王座》GPT 重制首集的 18 个源视频均正常，但 14 个转码缓存出现 H.264 数据损坏；旧合并结果仅 18.309 秒。时长和尺寸元数据仍能读出，所以原来的 FFprobe 检查错误地接受了缓存。

导出启动接口和状态接口都会恢复任务，而 Next 的不同路由构建产物不保证共享模块内的 `activeJobs`。因此仅靠 Map 不能阻止两个执行器写相同的转码文件。这是代码中确认存在的并发缺口；独立模块回归模拟这两个入口。

修复采用每个导出任务的磁盘排他租约，跨路由和进程生效。拥有者还活着时不按经过时间抢占；拥有者退出后可以恢复，清理时只删除原拥有者的唯一文件名，不递归移除新的租约。FFmpeg 写入唯一临时文件，完成并验证后才原子替换正式缓存，因此崩溃后遗留的子进程不能发布半成品。

源文件、转码缓存和最终成片现在都用 `-xerror` 完整解码检查。转码缓存还检查对应的预期剪辑时长，成片检查所有片段的合计时长。损坏缓存仅重新转码，正常缓存继续复用，不调用生图或视频生成 API。已标完成但损坏的旧导出同样可以恢复，下载接口拒绝交付坏文件。

真实首集复用了原 18 个视频，恢复导出为 130.443 秒，完整解码通过；这仅证明技术合成恢复，画面、对白、环境声及末镜无配音区间仍需另行验收。运行证据保存在 `outputs/gpt-season-remake-20260901/ep1-export-*.json`。

回归：`tests/companion-export-lease.test.mjs` 验证并发争用、活进程保护和死进程恢复；`tests/local-video-export.test.mjs` 验证独立路由实例轮询、损坏数据但元信息可读的缓存、短成片恢复及正常缓存不被重做。末镜一秒保护由 `tests/film-ending.test.mjs` 和 `tests/video-pacing.test.mjs` 覆盖。
