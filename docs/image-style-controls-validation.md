# 生图风格控制：实施与实测

2026-09-05；0.1.195 基线上的本地未发布改动。用户授权付费图片与四格案例，不涉及 H3、视频采样、LoRA 或生产质检。

## 修正后的职责

- 新建 Story 默认“跟随参考”：不叠加通用摄影风格。已有项目保留原选择。
- 用户明确选择制作风格时，发送对应成像媒介、色彩、光线、材质指令；明确选择拍摄方式时，发送对应镜位、透视、景深与曝光指令。不可因为有角色母版而静默忽略。
- 人物参考约束身份与服装设计，产品参考约束产品设计，剧本约束动作。独立风格参考只负责视觉语言；明确制作媒介优先，不能从风格参考复制第二个人物或产品。
- MJ 通过原生 sref/sw 传风格图；GPT 通过独立编号的参考图和职责说明实现，不伪装成 GPT 原生参数。角色页局部风格图权重不再被全局 URL 缺失吞掉。
- 角色页风格、拍摄方式、风格图和说明可保存草稿，刷新恢复；可展开查看生图风格指令。Story 修改风格对已有素材提示重新生成，并标记旧视觉结果失效，不自动付费重做。
- Series 继续走原有 styleReference 与共享生图出口，不静默丢弃参考图。相机型号/焦距/光圈/ISO 截图属于独立图生视频页，本轮未改。

## 代码入口

`lib/imageStyleControls.ts` 是生图专用优先级与预设组合；角色 API、单幅 GPT、四格、定妆/场景复用。既有 `lib/promptArchitecture.ts`、`lib/capturePresets.ts` 仅引用，未修改视频合同；H3 和云端工作流未改。

## 验证

- 191/191 项回归通过，包含 9×9 指令组合、API 参数、参考图排序/容量、Story 序列化与 H3 兼容测试；不是 81 次付费图片验收。
- `npm run build` 通过；`tests/character-design-ui-smoke.mjs` 隔离浏览器 mock 验证选择、上传、sw=300、刷新恢复及原角色流程通过。
- 真实付费任务 10 个：2 MJ（无 sref / sref=原母版，sw=300）、5 GPT 人物（暖片/黑色/动漫/定格/3D）、3 GPT 四格（电影/监控/独立冷色风格图）。全部一次完成，没有自动重提。
- 视觉结果：暖冷、动漫、定格差异清晰；四格额外风格图确实生效，人物与服装主要设计延续。监控机位仅部分达成：俯视与空间覆盖增强，但仍偏精致，不能宣称严格 CCTV 全景已完全实现。胶片细颗粒也不充分。
- 本轮没有产品原图、多角色、全部拍摄预设的付费验收；没有视频测试。生成模型不是确定性相机/身份锁。

完整原图、比较、实际应用输入和回执：`outputs/image-style-controls-20260905/案例画廊.md`。`*-provider-payload.json` / `*-prompt.txt` 是同版编译器从真实保存输入离线复算，非网络抓包。导出脚本无付费网络调用；不要为查看案例再次运行提交命令。
