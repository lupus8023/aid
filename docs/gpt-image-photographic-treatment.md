# GPT-image-2 摄影质感规则

来源：用户提供的五组摄影提示词；补充阅读 [Formulasearch 的案例整理](https://x.com/Formulasearch/status/2046790896482455890)。案例展示不等于模型一致性保证，不能把 “100% consistency” 等措辞当作已验证能力。

2026-09-01：根据用户随后提供的诊断、真人电影范本和示例图进一步精简。范本用于提取思路，不整段追加到请求。旧版每镜反复堆叠皮肤、材质、光学工程术语；即使都声称“真实”，也会把画面写成渲染规范。现在优先写可观察的摄影事实：

- 先写这一刻的动作、相机位置、人物遮挡关系和光线来源；不以通用风格段开头。
- 肤质只要求自然且不磨皮，保留原有年龄和标记。不逐镜列虹膜纤维、毛孔、汗毛、皮下散射，也不凭空制造雀斑、伤疤或妆容。
- 衣服和布景像现场实物；不要求每种表面都发亮、每处纹理都清楚，不新增泥污或湿润来制造真实感。
- 沿用剧情光源、时间和天气。允许暗部看不清、背景柔化、小灯过亮；不自动补美颜灯或轮廓光。
- 保留每镜指定的距离、焦点和景别。远景、群像、手机和监控画面不套固定微距人像或 85mm。
- 风格图只控制文化美术气质、色温色调和摄影氛围，不继承其绘画/CG媒介，也不复制人物、姿势和场地。

上游导演要求用约 55–95 个英文词写具体画面，不再强制逐镜填满光学技术清单；PBR、subsurface scattering、material response、microcontrast、highlight roll-off 等词只在导演的禁用说明中出现，不作为默认生图风格要求。最终请求仍保留必要的人物、参考编号和剧情约束，不能为了字数短而丢身份。手工填写的用户正文不通过黑名单擅自删改。

命名角色每个出现一次；只有剧本明确写出的无名侍从/群众才可作为背景保留。身份检查获得本镜上下文，不能一边要求抬灵柩的侍从、一边用总人数等于命名角色数量来判错。实际缺失命名角色仍是结构错误。

未采用固定年龄、国籍、三围、性感服装、指定摄影师、广告式“获奖/大师杰作”等与当前剧情无关的写法。动漫、3D、定格动画仍服从所选媒介。

实现入口：`gptPhotographicDetail.ts` 提供按用途和景别分配的规则；角色锚点、角色卡、候选卡、场景参考、单镜分镜和 GPT 九宫格调用。通用图生图只为 GPT 替换原先固定的棚拍规则，MJ 和其他模型不变。

测试覆盖默认请求不含渲染术语、非写实媒介不受影响、参考顺序/身份/物种保留、场景与人物景别区分，以及无名背景人物不会误伤命名角色检查。

本轮实际抽取第一集第 1、2、10 镜，各生成一次 GPT-image-2 单帧样片；沿用相同身份和场景参考，重新编写分镜正文，并简化风格文字。这是工作流前后抽查，不是固定 seed、只改变一个变量的实验。输出和实际提交的无密钥 API 请求保存在 `outputs/gpt-plain-photo-3shots-20260901/`；原先 18 镜的请求归档不覆盖。

不按主观“CG感”自动重生成。单组随机输出只能作视觉抽查，不能证明所有镜头都会改善，更不能保证完全消除 CG 感。已有角色或场景参考仍可能带入原来的外观倾向。
