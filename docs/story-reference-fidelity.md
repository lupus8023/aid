# Story 原图引用与分镜一致性

版本：0.1.194（2026-09-05）。Story 和通过 `/story` 执行的 Series 共用；网站与 Companion 需同步更新。

## 本次修复

1. `prepareStoryAssets` 在编剧前、首次新生图前准备已选原图。原图通过已有轻量上传链路转为 URL，不内嵌进剧本大请求。
2. `/api/prepare-story-assets` 使用所配置的支持图片输入的文本模型，一次最多理解 8 张原图，输出简短外观事实、可见相对尺度、允许的物理状态，以及 character/packaging/product/material/prop 用途。
3. `visualIdentity` 随项目持久化，源图、名称、用户说明变更才失效；本地后台另存原图理解草稿用于断点复用。不是生成后质检，不读取已生成分镜，不对画面打分或循环重生。
4. 原用户说明与选角身份保留，视觉事实单独传给编剧与导演。不会仅因增加外观说明就改变 `storyCastKey`、废弃成功选角或重写已保存分集。包装不等于内容物，材质图不应变成额外物体；原图事实优先于名称中的颜色词和冲突的旧描述。
5. 已登记角色别名、静默出镜标签、固定 ID 都参与选图。绑定保留名称快照，用户修改镜头出场名单时旧绑定失效，角色卡改名则仍可按固定 ID 找到原图。
6. 四宫格完整保留每镜动作、参考用途、人物服装和场景说明，不再将动作截为 96–200 字符，也不删除参考说明。GPT 四宫格使用较大的现有请求空间；有较小输入上限的路径在提交前改为完整逐镜请求，不购买一个注定缺图/缺动作的四宫格。
7. 图片、用途、编号作为同一列表保留；风格图占位前后统一。前后台不静默截断角色/环境图，底层旧原图上传失败也停止，不让后续编号错位。单镜输入超长先减少重复规则，仍放不下则在提交前说明容量问题，不截断正文。
8. 仅禁止叠加字幕/UI/标题等，保留原产品表面的真实标签与印字。柔性膜片可折叠、下垂、贴脸，不以“绝不变形”阻止原剧本动作。

## 恢复与部署

- 已成功图像、已付费任务不失效、不重提。续查已有四宫格/单图任务跳过原图理解；新生成或手动重生成才使用新链路。
- 已有错误图片不会因为代码修复而自动改变；不自动付费替换这些素材。
- 新图使用完整参考约束；已保存的旧分镜文字不被偷偷重写。若旧稿已经把包装写成贴脸膜体，应先重新整理分镜提示词再手动生成受影响的镜头，不能仅靠重新下载修复旧图。
- 新增 `/api/prepare-story-assets` 并加入 Companion CORS。发布需同步网站与 Companion；仅刷新旧 Companion 上的网页不足以提供新接口。
- 文本模型需要支持图片输入，设置页已注明；识图失败明确提示，不能伪造资产事实继续生图。
- 只做离线模拟与构建验证，不据此承诺模型生成的视觉一致性达到 100%。

## 验证入口

`npm run test:story-assets` 覆盖原图实际传入模型、缓存/变更失效、包装膜片区分、别名与固定 ID、手动移除绑定、完整动作到 API、风格占位、付费任务恢复、轻量上传原始字节与顺序。

更多背景：Obsidian 的 `aid-Story产品与人物一致性排查-2026-09-04`。
